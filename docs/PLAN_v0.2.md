## 1. 한 줄 정의

**HCG가 4~6주 걸려 하던 조직·인사 진단을, 같은 방법론으로 2주 만에, 몇 분의 1 가격에 받는 플랫폼.**
고객은 둘 중 하나로 들어온다.

- **HR 헬스체크** — "우리 인사제도 전반이 어디가 아픈지 모르겠다" → 전 영역을 넓게 보고, 어디를 깊게 봐야 하는지까지 알려준다.
- **모듈 딥진단** — "평가가 문제다", "보상이 안 맞는다"처럼 니즈가 있는 고객 → 해당 모듈만 골라 깊게 본다.

두 경로 모두 결과는 "이슈 → 근본 원인 → 개선 방향 → 처방(다음 상품)"으로 끝난다.

## 2. 해자 — 다른 컨설팅사가 따라 할 수 없는 이유

자료를 다 보고 내린 결론: **HCG의 해자는 '설문'이 아니라, 20년간 반복 검증된 진단 프레임워크·판정 기준·이슈 패턴·설계 옵션이 하나의 체계로 엮여 있다는 것**이다. 지금은 이게 PPT 수백 장에 흩어져 있고 컨설턴트 머릿속에서만 연결된다. 플랫폼은 이것을 **구조화된 데이터베이스 + 자동 분석 엔진**으로 바꾼다.

| 해자 자산 | 출처(자료) | 플랫폼에서의 형태 |
|---|---|---|
| **HR / Organizational Health Check Framework™** — 인식(Awareness)·사실(Fact)·벤치마킹·정합성(Alignment)·**말과 실제의 차이(Say-Do)**·준비도(Readiness) 6분석 | CS WIND, LDCC, 율곡, 아시아나IDT, Airfirst, 코린도 | 헬스체크의 뼈대. 설문=Say, 문서·데이터=Do/Fact, 둘의 차이를 자동 계산 |
| **ODS / 3E 진단 모델** — 투입(Hard)→과정(Soft)→결과(Emotional) 14영역, 3E 45항목 | TMax, LEM, EX진단, SK머티리얼즈, 정식품, NSK | 표준 문항 뱅크(79·93·45문항 실제 문항 확보) + 영역별 Key Question |
| **HR Maturity Level 4단계** — Reactive / Systematic / Strategic / Agile, 8영역 × 4요소 판정 기준 | LEM PMI, 경동인베스트, 정식품 | 제도 문서로 AI가 수준 판정 → 영역별 Lv 1.0~4.0 |
| **HR Snapshot™** — 영역별 운영수준(Maturity)·전략적 중요도(Significance)·HR 운영역량(Capability) 3축 | 코린도, 정식품 | 헬스체크 결과의 첫 장 차트 |
| **Agile Performance Circle®** — 성과관리 8영역 × 4단계 판정 기준 | 롯데월드 | 평가·성과관리 딥진단의 뼈대 |
| **분석 방법론** — 긍정응답률, 무성의 응답 제외, 인구통계별 Heatmap, Top/Bottom 5, **IPA(중요도=결과변수와의 상관)**, **직원 유형 4분면**(Effective·Detached·Ineffective·Frustrated), **회귀 β 근인분석**, Employee Typology 7유형, 만족×몰입 Matrix, 텍스트 토픽·정서 | 한림, 동희, 안랩, TMax, EX진단, NSK, SK머티리얼즈 | 자동 분석 엔진 |
| **HR Fact 분석 팩** — 규정 배분율 vs 실제 등급 분포, 1차 평가자 관대화, 2차 평가 등급 변경률, 승진 대상자 점수 부풀림, 실제 승진 체류연한, 승진율 vs 동종사, 직급-역할 불일치, 5명 이하 팀 비율(상대평가 불가), 연봉 분포 Overlap, 매출 대비 인건비율 등 | 동희, HMM, TMax, 한림, 에이블씨엔씨, SM | HR 데이터 업로드 → 자동 계산 |
| **이슈 라이브러리** — 영역·이슈·근거·**근거 확실성**·시사점 / Key Issue 선정 기준(①직원 불만이 큰가 ②몰입·재직·타 이슈에 파급이 큰가) | TMax(70개→16개), KKM, HMC(22개), 기아 | 진단 결과를 표준 이슈에 매핑, 누적될수록 정확해짐 |
| **Design Library** — 평가·보상 **100개 설계 요소 × 요소별 2~4개 대안**, Question Tree | SKDY, 경동인베스트 | 진단 이슈 → 관련 설계 질문 자동 연결 = 다음 상품(설계)의 입구 |
| **세부 툴** — KPI 적정성 점검(Goal Grid·가중치 필터·Target Level), KPI 타당성 5기준, CSF Matrix, 정성평가 Grid, 리더십 Derailer Pool, 평가 수용성 체크리스트, R&R 비효율 6유형, 업무 속성 판정 트리, 우선순위 Matrix | HMM, 정식품, Airfirst, KKM, 하이트, 아시아나IDT 등 | 딥진단 모듈 안의 자동 점검 |

**쌓일수록 강해지는 구조:** 진단이 끝날 때마다 ① 문항별 응답 분포(→ 업종·규모별 기준값), ② 이슈와 근거, ③ 실제 계약된 처방이 쌓인다. 경쟁사가 같은 화면을 베껴도 이 세 가지는 베낄 수 없다.

## 3. 상품 구조

```
            ┌───────────── [0] 셀프 체크 (무료·15분) ─────────────┐
            │  CEO/인사담당 20문항 + 공개 정보 → 의심 이슈 3개      │
            └──────────────┬──────────────────────┬──────────────┘
                           ▼                      ▼
       [A] HR 헬스체크 (넓게)              [B] 모듈 딥진단 (깊게, 1개 이상 선택)
       전 영역 · 2주                       평가·성과 / 보상 / 직급·승진 / 조직·R&R /
       결과: HR Snapshot,                  인력·적정인력 / 조직문화·EX / 리더십 / 직무·역량
       핵심 이슈, "깊게 볼 모듈" 추천 ──▶   결과: 모듈별 이슈·근인·설계 방향
                           └──────────┬───────────┘
                                      ▼
              [C] 처방: 설계 워크북(Design Library) · HCG 설계 컨설팅 · ATEAM 운영
```

- 헬스체크를 받은 고객에게는 **"점수가 낮고 영향력이 큰 모듈"을 딥진단으로 추천**(IPA 결과 기반).
- 니즈가 분명한 고객은 헬스체크 없이 바로 모듈 딥진단. 단, 모든 딥진단에는 **헬스체크 축약판(Outcome·Direction 핵심 문항 10개 내외)**을 기본 포함해 "이 문제가 몰입·재직의도에 얼마나 영향을 주는지"를 함께 보여준다.
- 모듈은 조합 가능(예: 평가 + 보상). 공통 문항·인터뷰는 한 번만 진행.

## 4. 진단 흐름 — HCG 실제 프로세스를 그대로

HCG 진단의 공통 순서는 자료 전반에서 같다: **사전 가설 → 수집 → 분석(기본·심층·근인) → 이슈 구조화 → 방향·과제·우선순위**. 플랫폼도 이 순서를 따른다.

| 단계 | 기간 | 내용 | 근거 자료 |
|---|---|---|---|
| ① 사전 가설 | Day 1 | 제도 문서·인력 명단·(선택) 공개 정보를 AI가 빠르게 훑어 **가설 이슈 목록**(근거 확실성 표기) 생성 → 고객이 확인 | KKM(문헌 Quick Review로 가설 → 인터뷰 검증), 기아 이슈 리스트, DB하이텍(인력구조 데이터로 가설), 솔루엠(잡플래닛·블라인드로 가설) |
| ② 맞춤 설계 | Day 1~2 | 표준 문항 + 가설 검증용 맞춤 문항, 대상별 인터뷰 질문 확정 | 현대오토에버·SK머티리얼즈(진단 Modeling), 스마일게이트(Logic Tree → 질문) |
| ③ 수집 | Day 2~10 | 직원 설문(링크) · AI 인터뷰(임원/조직장/직원 트랙) · 문서 · HR 데이터 | 전 자료 공통 |
| ④ 분석 | Day 10~12 | 기본(긍정률·그룹별) → 심층(Heatmap·IPA·유형·텍스트) → 근인(회귀 β, Say-Do 차이) | CS WIND·LDCC 분석 3단계, 한림·동희·TMax·NSK |
| ⑤ 이슈·처방 | Day 12~14 | 이슈 풀 → Key Issue 선정 → 근인 구조도 → 개선 방향 → 과제(Quick Win 포함) → 우선순위 Matrix → 처방 모듈 | TMax, LEM, CS WIND(Quick Win 정의서), 하이트·LEM·TSC(우선순위) |
| ⑥ 검수·발행 | Day 14 | HCG 컨설턴트 검수 후 발행 (결정 필요 ③) | — |

### 4.1 수집 도구 (Say · Do · Fact)

| 도구 | 무엇 | 플랫폼 구현 |
|---|---|---|
| **직원 설문** (Say) | 리커트 5점 + 선택형 Top3 + 주관식 2 | 링크·QR, 익명, 응답률 실시간, 무성의 응답 자동 제외, 5명 미만 셀 숨김 |
| **AI 인터뷰** (Say, 맥락) | 대상별 트랙: 임원 / 조직장 / 직원 | TMax·KKM·HMC 질문표를 뼈대로 AI가 꼬리질문. 인터뷰 끝에 **이슈 우선순위 미니 설문**(PSS 방식) |
| **제도 문서** (Fact) | 평가·보상·승진 규정, 직급표, 위임전결, 업무분장 | AI가 구조표 추출 → **HCG Check Point·Maturity 판정 기준**으로 수준 판정 |
| **HR 데이터** (Fact) | 인력 명단(직급·직책·근속·연령·조직), 평가 결과, 연봉, 승진 이력 | 업로드 즉시 자동 분석(4.2). 이름 열 거부, 사번은 해시 |
| **공개 정보** (선택) | 공시(매출·인건비·평균연봉), 채용 리뷰 | 매출 대비 인건비율·인당 매출 등 동종사 비교. 리뷰 사이트 활용은 약관 검토 후 결정 |

### 4.2 분석 엔진 (자동)

- **기본:** 영역·항목·문항별 평균과 긍정률, 조직·직급·직책·근속·세대 Heatmap, Top 5 / Bottom 5, 선택형 Rank, 응답 경향(이해도는 높은데 만족이 낮은 문항 등)
- **심층:** IPA(각 영역이 몰입·만족에 주는 영향 × 현재 점수 → 중점 개선 / 장기 개선), 직원 유형 4분면(Driver × Outcome), 만족×몰입 Matrix, Employee Typology 7유형 분포, 주관식 토픽·정서, 인터뷰와 설문이 서로 다른 지점 표시
- **근인:** 재직의도·몰입·만족에 대한 회귀 β, **Say-Do 차이**(예: 설문은 "평가 기준이 명확하다" 60%인데 실제 데이터는 상위등급 배분이 규정과 어긋남)
- **기준값 비교:** "타사 평균 대비", "하위 10% 기업 대비"(HMM 방식). 초기에는 HCG 과거 결과로 시드(10장 참조)
- **해석 가이드 내장:** "HR 효과성·성과관리·보상 형평성은 대부분 조직에서 통상 낮게 나온다" 같은 컨설턴트의 판단 기준을 리포트 문장에 반영

### 4.3 이슈·처방 엔진

1. 분석 결과를 **이슈 라이브러리**에 매핑 → 이슈 풀 (영역 / 이슈 / 근거 출처 / **근거 확실성: 확실·가능성 높음·통상 그러함** / 시사점)
2. **Key Issue 선정** = 중요도(직원 불만 수준) × 영향력(몰입·재직·타 이슈 파급) — TMax 기준 그대로
3. **근인 구조도** — 이슈 간 인과를 묶어 "본질 이슈는 무엇인가"(CS WIND·정식품의 이슈 구조도 형식)
4. **개선 방향 → 과제**, 과제마다 Quick Win 정의서(개요·목적·선결·기대효과·기간·KPI·R&R)
5. **우선순위 Matrix** — 전략적 중요도 × 개선 시급성(LEM), 또는 중요도 × 난이도(TMax)
6. **개선 항목 간 연계 검증** — 직급·평가·보상·승진 간 선후·충돌·누락 확인(LDCC·동아쏘시오)
7. **처방 연결** — 과제별 HCG 설계 상품 + Design Library 질문

## 5. [A] HR 헬스체크

### 진단 모델

TMax ODS 14영역을 기준으로 표준화. LEM(3E)·NSK·한림·동희가 쓴 '투입→과정→결과' 구조와 같다.

| 층 | 영역 | Key Question (TMax 원문 기반) |
|---|---|---|
| 투입(Hard) | 비전·전략 | 구성원이 비전과 전략을 이해하고 공감하는가? |
| | 조직구조 | 조직구조는 전략 실행에 적합하며 적절히 분화되어 있는가? |
| | 업무 프로세스·R&R | 절차가 체계적이고 권한과 책임이 명확한가? |
| | 인사제도 | 인사제도를 이해하고 만족하는가? (직급·평가·보상·육성·채용·인력운영) |
| | 업무환경 | 업무 수행에 적합한 환경과 업무량인가? |
| 과정(Soft) | 리더십 | 경영진·직속상사의 리더십과 신뢰 수준은? |
| | 소통·협업 | 수평·수직 소통과 협업이 원활한가? |
| | 조직문화 | 현재 문화와 기대하는 문화는? (People·System·Change·Result 4유형) |
| | 다양성·포용 | 인정·존중·포용 수준은? |
| | 인력(People) | 인력이 양·질 모두 충분하고 배치가 적절한가? |
| 결과 | 직무만족 · 조직몰입 · 재직의도 · 동기/저해 요인 | 구성원은 만족하고 몰입하며 남고 싶은가? 무엇이 동기를 주고 꺾는가? |

- 설문: 표준 **약 50문항**(LEM 79문항·TMax 93문항에서 핵심만) + 선택형 심층 4개 + 주관식 2개 + Typology 4개. 15분 내 응답
- 인터뷰: 임원·조직장·직원 3트랙 × 9영역 질문표(TMax 인터뷰 질의서 기반)
- 문서·데이터: 인사 규정 일체 + 인력 명단(필수), 평가·연봉 데이터(선택)
- **HR Maturity 판정:** 8영역(직군·직급·승진·평가·보상·교육·채용·핵심인재) × 4요소 = 32개 요소를 문서 + 담당자 확인 질문으로 Lv1~4 판정

### 헬스체크 리포트 목차

1. 경영진 요약 — **HR Snapshot**(영역별 운영수준·전략적 중요도·HR 운영역량), Key Issue 3~5개, 추천 딥진단 모듈

4. 개선 우선순위 — IPA Matrix
5. 제도 성숙도 — 8영역 Maturity Lv와 다음 단계 모습
6. 말과 실제의 차이(Say-Do) — 인식과 문서·데이터가 어긋나는 지점

## 7. 처방 연결 — Design Library

- SKDY·경동인베스트 방식: 진단으로 **현재 Maturity → 목표 Maturity**를 정하고 → Design Library의 해당 설계 요소에 답하면 → 설계 가설이 나온다.
- 플랫폼에서는 진단 이슈와 Design Library 질문을 연결해, 리포트 마지막에 "당신 회사가 결정해야 할 설계 질문 12개"를 보여준다.
  - 예) 이슈 "5명 이하 팀 과반 → 상대평가 불가" → 설계 질문: 평가 그룹 단위 / 등급 분포 방식(제한적 상대·제한적 절대·절대) / 재원 통제 방식
- 다음 상품 세 가지:
  1. **설계 워크북**(셀프 + 컨설턴트 리뷰): 고객이 직접 옵션 선택
  2. **HCG 설계 컨설팅**(범위·기간·가격이 정해진 패키지)
  3. **ATEAM 도입**(평가·성과관리 운영)

## 9. 기술 구조

- **프론트:** React 19 + Vite + TS + Tailwind + React Query (ATEAM과 같은 구성, 같은 디자인 체계) → Vercel
- **백엔드:** Supabase (Auth · Postgres + RLS · Storage)
- **AI:** Edge Functions에서 Claude API (긴 글은 Sonnet, 분류·요약은 Haiku)
- **분석:** 통계(긍정률·상관·회귀·IPA)는 **Postgres 함수 + Edge Function 안의 TypeScript**로 결정적으로 계산하고, AI는 해석과 문장만 담당 (숫자를 AI가 만들지 않게)

### 방법론 DB (해자의 실체)

### Edge Functions와 JWT 설정

| 함수 | 역할 | Verify JWT |
|---|---|---|
| `survey-submit` | 링크 응답 저장 | **끔** — 로그인 없는 응답자, 함수 안에서 일회용 토큰 검증 |
| `ai-interview` | AI 인터뷰 진행 | **끔** — 링크 대상자, 함수 안에서 토큰 검증 |
| `ai-hypothesis` | 문서·명단 → 가설 이슈 | 끔 — 함수 안에서 사용자 토큰 확인 |
| `ai-doc-extract` | 규정 → 구조표·Check Point·Maturity 판정 | 끔 — 함수 안에서 사용자 확인 |
| `fact-analyze` | HR 데이터 자동 분석 | 끔 — 함수 안에서 사용자 확인 |
| `analyze-survey` | 통계·IPA·유형·회귀 | 끔 — 함수 안에서 사용자 확인 |
| `ai-report` | 이슈 매핑·문장 생성 | 끔 — 함수 안에서 사용자 확인 |
| `self-check` | 셀프 체크 채점 | 끔 — 함수 안에서 사용자 확인 |

ATEAM과 같이 전부 Verify JWT를 끄고, 응답자용 두 함수는 링크 토큰으로, 나머지는 함수 안에서 로그인 사용자를 확인.
